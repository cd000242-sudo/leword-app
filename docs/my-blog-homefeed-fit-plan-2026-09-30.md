# 내 블로그 특화도 — 두 층 플랜 (2026-09-30, 실측 뒤 재정리)

사장님 과제: "내 블로그를 주면 알고리즘이 어디에 특화되어 있나 파악 → 어떤 걸로 어떻게 써야 홈판에 유리한지".
방향(확정): **사이트 층 = 앱 없이 공개 실측으로 완결 · 앱 층 = 같은 표 + 로그인 실측(홈판 유입) 덧붙임 · 계정 동기화로 사이트에도 표시.**
"앱에서 하세요" 안내판·앱 카드 복사본 금지. 추정치(확률·예상 트래픽) 금지 — 실측·단순 산술·매칭 사실만.

## 0. 실측으로 확정된 바탕 (2026-09-30, 93건 호출, 비용 0)

- 어드바이저 `/api/v6` 는 **앱 로그인 세션만으로 창 없이** 부를 수 있다(커밋: advisorFetch). 3요건 = 로그인 쿠키 + 서명(`__ca_key`, 30분 만료·403 시 1회 재발급) + Referer `/naver_blog/<channelId>`.
- 살아 있는 창구 66개. 이번 플랜이 쓰는 것만:

| 묻는 것 | 창구 | 준다 |
|---|---|---|
| 내 글이 홈판을 탔나(글별) | `inflow-analysis/referrer-domain?contentId=` | "네이버 메인_모바일_홈판" 건수·비율 |
| 어제 유입 있던 내 글 | `integrated-analysis/cv-ranks(day)` | 글 URL·조회 |
| 내 유입 주제 | `integrated-analysis/d1-ranks(day/week)` | 주제별 유입("자동차" 64) |
| 내 주제 인기 검색어 | `home/popular-category-keyword(week=월요일)` · `trend/category?categories=자동차(day)` | 검색어 10 / 20 + rankChange |
| 오늘 홈판 탄 글 전체 | `trend/main-inflow-content-ranks(day)` | 제목·URL |

- 한계(그대로 표기): "왜 홈판을 탔는지" 이유는 어디에도 없다 — 탔다/안 탔다·건수·판만. 유입 0 인 검색어 창구(query-competitiveness 등)는 0.
- **아직 안 잰 것**: 어제 통계가 아침 몇 시에 채워지는지. 수집 시각은 이걸 재고 정한다(1단계 첫 항목).

## A. 앱 층 — 하루 1회 어드바이저 수집기

목표: 앱이 켜져 있으면 사장님이 아무것도 안 눌러도 하루 한 번 위 창구를 돌려 `userData/advisor-daily/YYYY-MM-DD.json` 을 쌓는다.

- 전제: "로그인 상태 유지" 체크 로그인(영구 쿠키, 재시작 후 유지 실측 확인). 세션 없으면 **조용히 건너뛰고** 화면엔 "네이버 로그인 전" 사실 한 줄.
- 요청 수(하루): 기본 창구 9 + 글별 referrer-domain(어제 유입 있던 글, 상한 30) ≈ 40. 비용 0. 창구 하나가 429/5xx 면 그 창구만 `missing` 표기(전체 실패로 안 만든다).
- 스케줄: 기존 05:00 자리 실측 스케줄러(A3 감시) 옆에 붙임 + 회차 문지기(그날 파일 있으면 skip) + 앱 켤 때 오늘 것 없으면 1회. 수집 시각은 0장 "안 잰 것" 실측 뒤 확정.
- 저장: 날짜별 파일 90일 보존(어드바이저 day 창 상한과 같음) + `latest.json`. 응답에서 **계정 필드(nidId 등) 제거**, channelId 만 남김. 로그인 페이지 요청은 기록하지 않음(기존 규칙 유지).
- 앱 화면(내 블로그 화면에 표 3개, 인라인 스타일):
  1. **내 글 홈판 실적** — 글 제목·날짜·홈판 유입 건수·비율(실측). 정렬 = 홈판 건수.
  2. **내 유입 주제** — d1-ranks 순위 + 32주제 비교(metricValue) 옆에 나란히. "내 주제 / 판 크기" 두 숫자만.
  3. **오늘 홈판 탄 글(전체)** — 제목 목록 + 제목 낱말 빈도(실측 셈, 임의 분류 없음) + 내 주제 인기 검색어.
- 파일(예정): `src/utils/advisor/daily-plan.ts`(창구 목록·날짜 규칙 순수 함수) · `src/utils/advisor/daily-summary.ts`(응답→요약, 계정 필드 제거) · `src/main/handlers/advisor-daily.ts`(스케줄·저장·IPC) · 테스트 2 · 렌더러 표 · preload 창구 등록(EXPECTED_NAV/라우터 등록표 양쪽).

## B. 동기화 — 앱 → 사이트(내 계정만)

개인 데이터라 홈판 공개본 발행(공개 JSON) 방식은 못 쓴다. **키 동기화(keySync)와 같은 길**을 쓴다:
- 사이트가 앱 브리지 `GET /v1/bridge/my-blog/advisor-daily`(신설, Origin=사이트만) 로 `latest` 요약을 읽고, 비밀번호 유도 키로 AES-GCM 잠근 blob 을 워커 KV 에 올린다(`advisor:<slot>`, 별도 키·상한 64KB, TTL 90일). 다른 기기는 pull.
- 서버는 평문·비밀번호를 모른다(keySync 와 동일). 앱 원본 파일 경로·창구 목록은 넘기지 않는다.
- 워커(tmp/cf-worker, git 밖)에 get/put 2액션 추가 — 배포는 deploy.js.

## C. 사이트 '오늘 쓸 글' 판

- 앱 없이 완결되는 열: 공개 실측(내 블로그 글 목록·제목 낱말·검색량·자리) — 이미 있는 내 블로그 판 재사용.
- 동기화되면 덧붙는 열: 홈판 유입 건수·내 유입 주제·인기 검색어. 열이 비면 열 안에 "앱 실측 전" 한 마디(안내판 구획 없음).
- '오늘 쓸 글' 후보 = 내 상위 유입 주제(d1-ranks) ∩ 그 주제 인기 검색어(popular-category-keyword·trend/category) ∩ 검색량 실측. 각 후보에 **근거 개수**(몇 창구가 가리켰나)와 **내 실적률**(그 주제 내 글 중 홈판 탄 글 수 / 글 수, 단순 산술)만 붙인다. 확률·예상 트래픽 없음.
