# 제휴 수집 복구 (2026-09-06)

## 확인된 문제

- 공개 파일은 2026-08-21 수집본(토스 126건, 브랜드커넥트 6건)에 정지.
- 기존 파서는 실행별 구분 없이 덤프 폴더의 과거 파일까지 재사용.
- 브랜드커넥트는 카테고리 추천만 파싱하고, 실제 응답이 있던 프로모션/이벤트 상품 목록은 누락.
- 토스의 로그인 실패도 브랜드커넥트 발행을 차단.
- 2026-09-06 실측: 브랜드커넥트 로그인 화면으로 이동, 상품 응답 0건. 인증 없이 동일 상품 API를 읽으면 403.
- 관련 Windows 예약 작업과 GitHub 제휴 수집 스케줄은 확인되지 않음. 자동 갱신이 연결됐다고 주장하지 말 것.

## 수정

실행별 원문 경로/매니페스트를 사용하고, 당일 실행에 실제 받은 성공 응답만 분석한다.
플랫폼별 수집일/확인일/상태를 보존한다. 실패/빈 목록/급격한 부분 응답으로 이전 정상 목록이나 날짜를 덮지 않는다.
공개 사이트는 플랫폼별 마지막 수집일과 갱신 실패를 표시한다.
인증 정보는 기존 로컬 브라우저 프로필에서만 사용하며 저장소/공개 JSON에 넣지 않는다.
Bright Data 사용 없음. 링크 발급/계정 변경 없음.

## 재개

1. `node scripts/affiliate-campaigns.js --login --sites=brandconnect`
2. 직접 로그인하고 상품 목록 확인 후 창 닫기.
3. PowerShell에서 `NAVER_SITE_REPO`를 최신 사이트 체크아웃으로 지정.
4. `node scripts/affiliate-refresh.js --sites=brandconnect --noAi`로 수집/분석/로컬 반영.
5. 새 상품과 플랫폼별 날짜, 검색량 자격증명 설정을 확인한 후 `--publish`로 명시적 발행.

`--skipScrape`도 24시간 넘은 덤프를 새 수집으로 사용하지 않는다.
종료 코드 3은 일부 플랫폼의 새 수집 미완료를 의미한다(마지막 정상 데이터는 보존).
검색량 API 설정이 현재 로컬 환경에 없다는 로그도 확인됨. 숫자를 임의로 만들지 말고 분석 자격증명 연결을 확인할 것.
정기 갱신은 로그인 갱신과 1회 정상 수집을 확인한 뒤 실행 환경을 확정하여 연결해야 한다.
